### F-P5-01 — plugin "Copy Name/Full Name" puts CP1250-mojibake on the clipboard

- Sites: S-B8-P5-001, S-B8-P5-002
- Defect class: DC-06
- Failure scenario: **regedt** (Registry Editor FS, enabled). Open
  `reg:\HKEY_CURRENT_USER\Software\` and navigate to any key or value whose
  name contains non-ASCII characters (installed software routinely creates
  them: `Software\Nero\Šablony`, `Software\JetBrains\…`, a user-created
  `Můj klíč`). Focus the item, invoke **Copy Name** (`CMD_COPYNAME`) or
  **Copy Full Name** / **Copy Path**. Paste into Notepad / the Tandem command
  line: the user gets `MÅ¯j klÃ­Ä` instead of `Můj klíč`. Independent of UI
  language — it depends on the *data*, and reproduces on a stock cs/pl/hu
  Windows (ACP 1250) as well as on ACP 1252.
- Data path: `src/plugins/regedt/fs2.cpp:505` `file.Name = DupStrA(name)` →
  `regedt/utils.cpp:82` `WStrToU8(...)` (UTF-8 by the v104 contract) →

  `src/zip.cpp:2427` `::CopyTextToClipboard` → `src/salamdr4.cpp:1268`
  `CopyHTextToClipboard(hglbCopy, …)` → `salamdr4.cpp:1310`
  `AddUnicodeToClipboard(text, textLen)` → `salamdr4.cpp:1027`
  `MultiByteToWideChar(CP_ACP, 0, str, …)`.
- Evidence:
  - `salamdr4.cpp:1027` — `unicodeLen = MultiByteToWideChar(CP_ACP, 0, str, textLen, NULL, 0);`
  - `salamdr4.cpp:1316` — `SetClipboardData(CF_TEXT, hGlobalText)` (the raw
    UTF-8 bytes go on `CF_TEXT` untouched).
  - `regedt/utils.cpp:82` — `if (WStrToU8(ret, size, str, -1) <= 0)`.

  regedt is `on`); **local to the plugin?** partly — the three regedt call
  sites are local (3 lines), but the *proper* fix needs a UTF-8-capable
  clipboard entry point at the boundary. One already exists without an ABI
  change: `CSalamanderGeneral::CopyTextToClipboardW` (`zip.cpp:2431`), so the
  plugin-local fix is `SplU8ToWAlloc` + `CopyTextToClipboardW` (the pattern
  `dbviewer/renmain.cpp:1332` and `mmviewer/renmain.cpp:194` already use).
  **Enumerable regression surface**: the callers of
  `CSalamanderGeneral::CopyTextToClipboard` in enabled plugins are
  `checksum/dialogs.cpp:1190` (hex digest — ASCII, unaffected),

- Failure scenario: **ftp** (enabled), any UI language. Set *Options →
  Configuration → Panels → File name format* to "lowercase" or "uppercase"

- FR-012 pre-classification: user-visible in a shipped configuration (yes,

## Notes

### N-1 — the legacy-plugin adaptation shim is dead and the SDK still advertises it

`PlugLegacyU8ToACP` / `PlugLegacyACPToU8` / `PlugLegacyACPToU8Alloc`
(`src/pluglegacy.cpp:8,23,45`) and the gate `PluginSupportsUTF8`
(`src/plugins.h:23`) have **zero** call sites, and cannot acquire one:
`plugins.h:14` `#define PLUGIN_REQVER 104` refuses at load every plugin built
for an interface older than the UTF-8 one, which is precisely the population
the shim exists for. `pluglegacy.cpp` is nevertheless still compiled
(`src/vcxproj/salamand.vcxproj:474`). Two comment blocks still describe the
layer as live and would mislead a plugin author or a future reviewer:
`plugins.h:16-19` ("*plugins built for older versions keep receiving the legacy
ANSI code page through the core's adaptation layer*" — three lines above the
`REQVER` that makes it impossible) and `spl_com.h:209-210`, the same sentence
attached to `CFileData::Name`. No failure scenario → Note, not a Finding.

### N-2 — `CSalamanderGeneral::LoadStr` has a wide sibling but no encoding contract

`LoadStr` (`zip.cpp:1625` → `salamdr2.cpp:34`, `LoadStringA`) and `LoadStrW`
(`zip.cpp:1637` → `salamdr2.cpp:129`) are both exported (`spl_gen.h:3095,3104`)
and neither documentation block states what encoding `LoadStr` returns. The
core has a third form, `LoadStrU8` (`salamdr2.cpp:89`), which is not exported.
Self-consistent use inside a plugin is fine; the defects appear only where the
ANSI result meets UTF-8 (F-P5-07, F-P5-09, F-P5-12), which is why the missing
sentence matters.

### N-3 — the archive-plugin DC-13 probes are the right tool for the wrong-shaped input

P3 handed over strict `MB_ERR_INVALID_CHARS` probes in `tar`, `uncab`, `uniso`
(enabled) and `unmime` (disabled). These probe an **archive entry name** to
decide whether the archive stores UTF-8 or a legacy code page — a question a
strict probe answers correctly, and the 066 obligation (probe via `SalU8ToW`)
does not apply because the value is not a core name. The residual issue is the
opposite direction: a core name in WTF-8 form written into an archive and read
back is classified as legacy and re-decoded through the ACP. Latent, and it
belongs to the F-P5-04 fix batch rather than to a separate change.

### N-4 — `CQuadWord` through varargs in regedt's information line

`regedt/fs4.cpp:479` `SalPrintf(buffer, 1000, formatA, selectedSize)` passes a
`CQuadWord` **object** where the format expects a scalar (ledger L45). Not an
encoding defect — undefined behavior — but it sits inside an ANSI
`ExpandPluralString` composition, so a fix touching that line should correct
both.

### N-5 — plugin listing buffers cap UTF-8 names in bytes

`CSalamanderDirectory::AddFile` (`zip.cpp:5868`) and `AddDir` (`zip.cpp:5966`)
refuse an item when `strlen(path) > MAX_PATH - 5` or
`file.NameLen > MAX_PATH - 5`. Since interface 104 both values are UTF-8, so
the effective limit is ~85 characters for CJK and ~127 for Cyrillic/Central
European names, on a core that has been long-path aware since feature 004. The
item is dropped with only a `TRACE_E("Too long path or file name!")` — no user
message. Same family as ledger L35 and the undocumented `MAX_PATH` buffers in
`spl_fs.h` (F-P5-06).

### N-6 — two unbounded compositions in the plugin loader (ledger L59/L60)

`plugins1.cpp:2166-2169` builds the plugin DLL path with
`GetModuleFileName(HInstance, buf, MAX_PATH)` → `strrchr(buf,'\\')+1` →
`strcpy(s, "plugins\\")` → `strcat(s, DLLName)` into `char buf[MAX_PATH]`
with no bound check; `plugins1.cpp:2184` `sprintf`s the UTF-8 plugin `Name`,
the full DLL path and `GetErrorText` into `char bufText[MAX_PATH + 200]`
(`:2154`). Both confirmed at the recorded lines. Not encoding defects, but the
first is on P1's `GetModuleFileName` seed (C-c) and the second composes a UTF-8
name with a `LoadStrU8` template, so both live in this review's files.

### N-7 — sftp's UTF-8 text getter leaves plaintext in freed memory (ledger L64)

`sftp/dialogs.cpp:41-54` `GetDlgItemTextU8` reads the control wide, converts
with `SplWToU8` and then `free(w)` without zeroizing; the helper is used for
password and passphrase fields. One `SecureZeroMemory(w, (wchars+1)*sizeof(WCHAR))`
before the `free` closes it. Recorded here because the vehicle is an encoding

### N-8 — the plugin-facing registry services are the pre-010 ANSI wrappers

`CSalamanderGeneral::SalRegQueryValue` / `SalRegQueryValueEx`
