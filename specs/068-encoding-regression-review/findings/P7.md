Two of the false positives matter beyond this rule:

- **`dialogs6.cpp:210` is inside the `/* … */` block that spans `dialogs6.cpp:19-377`** — commented-out code. P1's inventory lists it as a live
  `verified-correct` site (S-B2-P1-066); it is dead text. Cosmetic correction
  to the inventory, no product consequence.
- 18 of the 101 hits matched **only on the API's own name**: `GetShortPathName`
  / `GetFullPathName` / `GetLongPathName` satisfy `UTF8_IDENT`'s
  `\w*[Pp]ath[A-Z]\w*` alternative and `GetOpenFileName` / `GetSaveFileName`
  satisfy `\w*[Ff]ile[Nn]ame\w*`. Twelve of those 18 are genuinely defective
  (F-P1-06/21/24) — the rule reached the right answer for the wrong reason, and
  a naive "exclude the call name" fix would **lose 12 true hits**.

**Minimal changes** (four, all inside `scan_draft`'s `ansi-api-on-utf8-path` block):

1. Blank string literals before matching, so a diagnostic string cannot be a
   call: `STRLIT = re.compile(r'"(?:[^"\\]|\\.)*"')`, then match on
   `STRLIT.sub('""', ln)` and on the `STRLIT.sub`-cleaned `call_text` result.
   Removes 6 hits, loses none.
2. Skip lines inside a block comment. A whole-file mask is needed, and it
   **must skip `//` first**: this codebase's banner comments start `//****`,
   whose bytes 1-2 are `/*`; a naive scanner opens a block on the first banner
   and swallows the rest of the file (I reproduced exactly that — it silenced
   `codetbl.cpp`, `mainwnd3.cpp`, `svg.cpp`, `versinfo.cpp` entirely).
   Removes 2 hits, loses none.
3. Do not flag the legacy arm of a wide attempt: reuse `wide_fallback(lines, i)`
   (already used by `utf8-to-legacy-sink`) **plus** a same-line same-API test
   `re.search(r'(?<![A-Za-z_])' + re.escape(api) + r'W\s*\(', code)` for the
   ternary shape. Removes 5 hits, loses none.
4. Restrict the `UTF8_IDENT`/`UTF8_SOURCE` search to the **argument text**
   (`stmt[stmt.find("(") + 1:]`), and recover the twelve true hits the
   restriction would lose with two argument-independent sub-rules:
   - `TWIN_API` — an un-suffixed call to an API that has a UTF-8 facade twin in
     `src/common/salfileio.h` is a finding on its own (the house rule is the
     facade, so no argument test is needed):
     `(?<![A-Za-z_])(?:FindFirstFile|CreateFile|CreateProcess|ShellExecuteEx|DeleteFile|RemoveDirectory|CreateDirectory|MoveFile|MoveFileEx|CopyFile|GetShortPathName|GetFileAttributes|GetFileAttributesEx|SetFileAttributes)A?\s*\(`
   - `STRUCT_API` — the path travels inside a struct, so it is never visible on
     the call line: `(?<![A-Za-z_])(?:GetOpenFileName|GetSaveFileName|SHBrowseForFolder|SHFileOperation)A?\s*\(`

### 1.2 `cp-acp-utf8-source` — 11 hits · TRUE 8 · FALSE-POSITIVE 3 (all undecidable line-locally)

| Verdict | Sites | Evidence |
|---|---|---|
| TRUE (defective) | `fileswn0.cpp:341`, `fileswn2.cpp:150`, `shellsup.cpp:536` (F-P1-25, S-B5-P1-100/101) | primary CP_ACP widening of a UTF-8 full name before OLE/shell hand-off; no wide attempt anywhere |
| TRUE (defective) | `geticon.cpp:365` (F-P1-18), `shiconov.cpp:932` (F-P1-28), `snooper.cpp:584,733,770` (F-P1-16) | these *are* fallback arms, and they are defective for the DC-20 reason: the buffer is used even when the fallback also fails |
| FALSE-POSITIVE | `fileswn1.cpp:503`, `salamdr2.cpp:1721`, `shellib.cpp:1628` (S-B5-P1-106) | documented legacy arm after a failed `SalU8ToW`, result checked |

`wide_fallback()` does not suppress these three because its pairing window is
only `lines[i-3:i+1]` and it looks for `else`/`legacy`/`fallback` — the shapes
here are `if (wl == 0) { … }` (`fileswn1.cpp:500-503`),
`if (SalU8ToW(…) == 0 && MultiByteToWideChar(CP_ACP, …) == 0)`
(`salamdr2.cpp:1720-1721`), and a comment six lines up (`shellib.cpp:1623`).

**Minimal change — and a deliberate non-change.** A rule-local helper widens
the window without touching the shared `wide_fallback()` (which four *strict*
rules depend on; widening it could hide a strict finding):

```python
U8_ATTEMPT = re.compile(r'\bSalU8ToW\w*\s*\(')
FAIL_TEST = re.compile(r'==\s*0\b|==\s*NULL\b|\bif\s*\(\s*!|\belse\b|legacy|fallback|transitional', re.I)
def acp_fallback_arm(lines, i):        # rule-local, cp-acp-utf8-source only
    if not U8_ATTEMPT.search("".join(lines[max(0, i - 12):i + 1])):
        return False
    return bool(FAIL_TEST.search("".join(lines[max(0, i - 8):i + 1])))
```

Measured effect: 12 candidate lines → 4 flagged. It removes two of the three
false positives (`fileswn1.cpp:503`, `salamdr2.cpp:1721`) **but also silences
five TRUE hits** (`geticon.cpp:365`, `shiconov.cpp:932`, `snooper.cpp:584/733/770`)
— because they are structurally fallback arms whose defect is the *unchecked
result*, not the conversion. **Recommendation: do not add the helper.** With
only 11 candidate lines in the whole core, the honest form is marker-based
exemption:

```cpp
// encoding-check: allow cp-acp-utf8-source - legacy ACP arm taken only after
// SalU8ToW failed, result checked; contract B7 rule 2 requires this fallback
```

**Verdict: promotable to strict** once F-P1-25 (3 sites) and F-P1-16/18/28
(5 sites) are fixed and the 3 legitimate arms carry the marker → residual 0.
Before those fixes, strict mode would need 8 suppressions; keep report-only
until the fix wave lands, then promote in the same change.

### 1.6 `signed-char-name-byte` — 42 hits · TRUE 4 · FALSE-POSITIVE 38 · **premise void**

The rule has two branches. They must be separated:

- **`SIGNED_CHAR_TEST` branch — 9 hits, all FALSE-POSITIVE, premise refuted.**
  The whole product compiles with `/J` (`src/vcxproj/sal_base.props:14`
  `<AdditionalOptions>/MP /J %(AdditionalOptions)</AdditionalOptions>`, and
  `src/plugins/shared/vcxproj/plugin_base.props:16` for plugins), and startup
  asserts it (`salamdr1.cpp:3811-3821`). `char` is unsigned everywhere, so
  `name[i] <= ' '` cannot misjudge a byte ≥ 0x80. P3 records the same finding
  (seed C-f, Note N5, S-X-P3-017/018) and **refutes ledger L07** with it.
  Hits: `fileswn0.cpp:3075,3079`, `fileswn5.cpp:1882`, `fileswn8.cpp:110`,
  `safefile.cpp:586`, `salamdr3.cpp:1213`, `salamdr5.cpp:1199,1227`,
  `shellib.cpp:1524`.
- **`BYTE_TABLE` branch — 33 hits, the shape P3 *confirmed*** (F-P3-06: ACP
  byte tables applied to UTF-8). 29 of the 33 index the table with a **drive
  letter** or a path's first byte in a `'a'..'z'` range test — ASCII by
  construction, false positives. The 4 that survive are the real ones.

**Decision: drop the signed-char branch, repurpose the rule as
`acp-byte-table-on-name`.** Keeping the dead branch would train readers to
ignore the rule (the 042 lesson quoted in `wide_fallback`'s docstring).
Narrowing regex (drop a hit whose table index is a drive-letter shape):

```python
BYTE_TABLE = re.compile(r'\b(?:IsNotAlphaNorNum|IsAlpha|LowerCase|UpperCase)\s*\[')
DRIVE_SHAPE = re.compile(r"\[\s*\*?\w+\s*(?:\[\s*0\s*\])?\s*\]\s*(?:[<>]=?|==|!=)\s*'[A-Za-z]'|"
                         r"\[\s*(?:drive|d|drv)\s*\]|\[\s*\w+\s*\[\s*0\s*\]\s*\]")
# flag when BYTE_TABLE and UTF8_IDENT match and DRIVE_SHAPE does not
```

Measured: 33 → **4 hits**, every one TRUE (F-P3-06):
`masks.cpp:49,52,327` (`LowerCase[*filename] == LowerCase[*mask]` — the panel's
mask matcher folds UTF-8 bytes through the ACP table) and `pack3.cpp:598`
(`&Extensions[LowerCase[archiveName[idx]]]`).

**Verdict: promotable to strict as `acp-byte-table-on-name`** once F-P3-06's
four consumer sites are fixed or annotated. Residual today: 4. Coverage it
does *not* have (state in the report): the table **definitions**
(`salamdr1.cpp:939-943`, `common/str.cpp:110-117`) and the `str.cpp` helpers
`StrICmp`/`StrNICmp` (S-X-P3-011) — those are one boundary each, reviewed by
hand, and a per-line rule would flag their whole implementation.

### 2.3 Three new rules — designed, measured on the current tree

**N1 `number-composed-across-statements`** (shape (a); DC-05/DC-19) — the
`ansi-template-number` rule matches only when the `NumberToStr`/`PrintDiskSize`
call is lexically *inside* the printf statement (P6 note N-08). Two-statement
composition is the common shape:

```python
NUMBER_DEST = re.compile(r'\b(?:NumberToStr2?|PrintDiskSize|ExpandPluralBytesFilesDirs|'
                         r'ExpandPluralFilesDirs)\s*\(\s*([A-Za-z_]\w*)')
TEMPLATE_DEST = re.compile(r'\b(?:sprintf|sprintf_s|_snprintf|_snprintf_s|wsprintf|strcpy|'
                           r'strcpy_s|lstrcpyn)\s*\(\s*([A-Za-z_]\w*)\s*,[^;]*\bLoadStr\s*\(')
# (a) format IS LoadStr(...) and an argument identifier was the destination of a
#     NUMBER_DEST call in the previous 12 lines
# (b) the FORMAT argument is an identifier that was itself filled from LoadStr(
#     by a TEMPLATE_DEST call in the previous 12 lines
# (c) literal format, but the arguments mix a NUMBER_DEST destination with a
#     buffer filled by strcpy(x, LoadStr(...))
```

Measured: **6 hits, no false positives** — `dialogs.cpp:951,970,973`
(P6 N-08/N-09, latent: mode-4 numbers are ASCII in every shipped locale),
`fileswn8.cpp:1404` (the parent-named site), `drivelst.cpp:2629` (shape (c),

**`fileswn8.cpp:1018`, which is F-P2-05's exact site**
(`sprintf(format, LoadStr(IDS_COPYDLGTITLE), expanded);` then

are fixed or annotated.

### 4.2 Does `wide_fallback()` mask the DC-16 shape (F-P3-05)?

**Yes — structurally, and it is not fixable inside that helper.** In the DC-16
shape the code is *correct at every line the guard can match*:

```cpp
if (SalU8ToW(...)) SetWindowTextW(hWnd, wide);   // the DEFECTIVE line
else SetWindowText(hWnd, u8);                    // suppressed by wide_fallback()
```

The wide call is the one that fails (USER32 thunks it back through the ACP
because the dialog came from `DialogBoxParamA`), and no rule matches a *wide*
setter — `SINK_WNDTEXT` deliberately excludes `SetWindowTextW`. The legacy arm,
the only line a sink rule could match, is exactly what `wide_fallback()`
exempts. So the guard is blind to DC-16 by construction, and widening
`wide_fallback()` (as §1.2 contemplates for another rule) would make more of
the file invisible, not less.

The switch is not on the setter's line at all — it is
`CWindowsObject::UnicodeWnd` (`src/common/winlib.h:131`, defaulting to `FALSE`,
`:272` deciding `CreateWindowExW` vs `A`). A rule for DC-16 must therefore be
class-scoped: collect classes whose `: CDialog(...)` / `: CCommonDialog(...)`
initializer does **not** pass `TRUE` for `unicodeWnd`, then flag `Sal\w*U8\s*\(`
and `\w+W\s*\(` text calls inside those class bodies. That is brace-tracking,
not a line rule; my recommendation is **not** to build it: DC-16 is closed by
construction (make the dialog Unicode, as the four existing Unicode windows
are) and tracked in the inventory, not by the guard. F-P3-05 / F-P6-03 /
F-P6-06 are recorded in §2.2 as structurally undetectable.

```cpp
    // (5) F-P3-02: srcLen == 0 is reported as a conversion FAILURE, although an
    //     empty string is a legitimate input - callers cannot tell it from
    //     malformed input (DC-20's sibling; salunicode.cpp:247 skips the WTF-8
    //     retry only for srcLen == 0).
    WCHAR w0[8];
    char c0[8];
    CHECK(SalU8ToW("", 0, w0, _countof(w0)) == 0);  // empty by length: "failure"
    CHECK(SalU8ToW("", -1, w0, _countof(w0)) == 1); // the same text by NUL: success
    CHECK(SalWToU8(L"", 0, c0, _countof(c0)) == 0); // the encoder agrees
    CHECK(w0[0] == 0 && c0[0] == 0);                // both still 0-terminate

    // (6) F-P3-09: capacity failure needs room for the terminator too - an
    //     "exact fit" buffer fails exactly like malformed input, which is why
    //     an all-ASCII selection can silently miss the wide shell path.
    WCHAR w3[4];
    CHECK(SalU8ToW("abc", -1, w3, 3) == 0); // 3 units + NUL > 3
    CHECK(SalU8ToW("abc", -1, w3, 4) == 4); // one more WCHAR is enough

    // (7) F-P3-03 (DC-09): the file facade REJECTS a path from an ANSI producer
    //     instead of falling back - the strict conversion is the whole gate.
    //     0xE8 is c-caron in CP1250 and is not valid UTF-8 in any locale.
    const char* acpPath = "C:\\\xE8"
                          "esta\\x.txt";
    SetLastError(ERROR_SUCCESS);
    CHECK(SalGetFileAttributes(acpPath) == INVALID_FILE_ATTRIBUTES);
    CHECK(GetLastError() == ERROR_INVALID_NAME); // never reached the disk
    CHECK(SalPathToWExtAlloc(acpPath) == NULL);  // and this is where it stops

    // (8) F-P1-08/F-P1-10 (DC-09) repair property: SalLegacyToU8Alloc is what
    //     makes an ANSI producer's path usable by the facade. Exact bytes are
    //     assertable only under CP1250 (the conversion goes through CP_ACP).
    if (GetACP() == 1250)
    {
        char* repaired = SalLegacyToU8Alloc(acpPath);
        CHECK(repaired != NULL);
        if (repaired != NULL)
        {
            WCHAR* wr = SalU8ToWAlloc(repaired);
            CHECK(wr != NULL); // convertible now, so the facade would accept it
            free(wr);
            free(repaired);
        }
    }

    // (9) F-P2-01/F-P6-02 (DC-19) mechanism: SalLegacyToU8Alloc's probe is
    //     ALL-OR-NOTHING. One legacy byte anywhere makes the whole buffer
    //     legacy, so the UTF-8 half is re-encoded and reaches the screen as
    //     mojibake - this is why an ANSI template plus a UTF-8 argument is a
    //     defect and not a cosmetic inconsistency.
    if (GetACP() == 1250)
    {
        //   "n<0xE1>zev: " (CP1250) + "<U+016F>" (UTF-8 C5 AF)
        char* mixedFixed = SalLegacyToU8Alloc("n\xE1"
                                              "zev: \xC5\xAF");
        //   CP1250 reads C5 AF as L-acute + Z-dot => C4 B9 C5 BB
        CHECK(mixedFixed != NULL && strstr(mixedFixed, "\xC4\xB9\xC5\xBB") != NULL);
        free(mixedFixed);
    }
    //   and the composed buffer itself has no wide path at all
    CHECK(SalU8ToWAlloc("Zobrazit polo\xBE"
                        "ku Obnoven\xC3\xAD") == NULL); // CP1250 z-caron + UTF-8

    // (10) F-P3-07 (DC-12): clamping a UTF-8 path in BYTES cuts a sequence, and
    //      the strict converter then refuses the WHOLE string - one truncated
    //      character costs the entire status-bar hint. The display converter
    //      keeps everything but the cut.
    char clipped[8];
    lstrcpyn(clipped, "abc\xC4\x8D"
                      "def",
             5); // 4 bytes + NUL: cuts C4 8D in half
    CHECK(SalU8ToW(clipped, -1, w0, _countof(w0)) == 0);
    CHECK(SalU8ToWDisplay(clipped, -1, w0, _countof(w0)) != 0 &&
          w0[0] == L'a' && w0[3] == 0xFFFD);
    //      the byte-safe way to clamp: walk characters, never bytes
    CHECK(SalU8CharCount("abc\xC4\x8D"
                         "def",
                         -1) == 7);
    const char* walk = "\xC4\x8D"
                       "def";
    CHECK(SalU8Next(walk) == walk + 2); // one character, two bytes

    // (11) F-P1-16/F-P1-18 (DC-20) caller property: on failure the converter
    //      0-terminates the destination, so a caller that ignores the return
    //      value gets an EMPTY string - never the indeterminate stack contents
    //      those two findings describe. The defect is the caller's, and this is
    //      the guarantee a fix can rely on.
    WCHAR poisoned[8];
    int k;
    for (k = 0; k < _countof(poisoned); k++)
        poisoned[k] = L'X';
    CHECK(SalU8ToW("\xC0\x80", -1, poisoned, _countof(poisoned)) == 0);
    CHECK(poisoned[0] == 0);

    // (12) WTF-8 stays byte-identical to UTF-8 for valid text, and the pair
    //      round-trips a lone surrogate through the display converter too -
    //      P1's and P6's operational sites all assume this (066 contract).
    WCHAR wtf[32];
    char back[32];
    CHECK(SalU8ToW(WTF8_REPRO, -1, wtf, _countof(wtf)) != 0);
    CHECK(SalWToU8(wtf, -1, back, _countof(back)) != 0 &&
          strcmp(back, WTF8_REPRO) == 0);
    CHECK(SalU8ToWDisplay(WTF8_REPRO, -1, wtf, _countof(wtf)) != 0 &&
          wtf[4] == 0xD800); // display keeps the true unit, not U+FFFD
```
