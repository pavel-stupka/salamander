## Working notes — house facts established (used by every row below)
- `SalGetTempFileName` (`src/salamdr3.cpp:216`) produces **UTF-8**: for
  `path==NULL` it calls `GetTempPathW`/`GetSystemDirectoryW` + `SalWToU8`
  (lines 223-244) and then creates the object through the UTF-8 facades
  `SalCreateFile`/`SalCreateDirectory` (lines 275/285). For `path!=NULL` it
  copies the caller's path, which is UTF-8 by the 004 contract. **Contract
  B9.5 compliant.**
- `ClearReadOnlyAttr` (`src/salamdr5.cpp:1464`) is UTF-8 (uses
  `SalGetFileAttributes`/`SalSetFileAttributes`).
- `SalGetFileAttributes`, `SalCreateFile`, `SalDeleteFile`, `SalFindFirstFile`,
  … (`src/common/salfileio.h`) take UTF-8 and fail with `ERROR_INVALID_NAME`
  on unconvertible input — so an ANSI producer feeding them is DC-09.

## Notes

- **N-1** — `CDiskCache::ClearTEMPIfNeeded` (`src/cache.cpp:1459-1535`) is the one place that deliberately keeps an ANSI chain end to end. It works today because the names it collects are 8.3-shaped ASCII, but the *directory* part is ACP and it is handed to two UTF-8 consumers (`RemoveTemporaryDir`, `WM_USER_FOCUSFILE`). Recorded as F-P1-03 rather than dismissed.
- **N-2** — *Install directory outside the ACP.* All the closed ANSI chains built on `GetModuleFileName` (A) (plugin `.spl` loading, `lang\*.slg`, `convert\`, `plugins.ver`, help enumeration, `salmon.exe`, restart) are lossless as long as the installation path is representable in the system ACP. They fail only for a path containing characters outside it (e.g. a Cyrillic-named folder on a CP1250 machine), where `GetModuleFileNameA` substitutes `?`. No shipped default does that (`C:\Program Files\Tandem Commander`), so this is **latent** — but it is one `GetModuleFileNameW` + `SalWToU8` away from being closed, and closing it would also close F-P1-10.
- **N-3** — All fifteen remaining `SetCurrentDirectory` (A) sites are labelled in the source as speed optimisations ("for faster operation", "so it runs faster", "for a faster move"). They fail silently on non-ASCII paths with no user-visible consequence, so they are Notes, not Findings (the sixteenth, `src/shellsup.cpp:2364`, is the already-fixed *Open With* site — feature 014's `SetCurrentDirectoryW` at :2360 with A as the fallback) — but they are also the reason the process CWD is *not* moved off a directory the user is about to delete, which is a (theoretical) sharing-violation source.
- **N-4** — DC-18 sweep result for `GetDriveType`: 26 remaining ANSI sites vs. one `SalGetDriveTypeU8` (feature 062, used at `src/salamdr2.cpp:1760/1771`). 24 of the 26 are provably ASCII (root built from a drive letter), 1 is defective (`src/shellib.cpp:2576`), 1 is a root-from-`GetRootPath` (safe unless UNC). Converting all 26 would be byte-identical for ASCII input and would remove the class.
- **N-5** — `src/worker.cpp:7062` contains a hard-coded developer path `"D:\\ZUMPA\\link"` in what looks like leftover experimental code. Worth deleting independently of this review.
- **N-6** — `DeleteThroughRecycleBinAux` (`src/fileswn8.cpp:22-32`, ANSI) is dead code after 062/005; the only caller uses the W twin. Deleting it removes a trap for future maintainers (and one guard false-positive).
