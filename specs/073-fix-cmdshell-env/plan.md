## Summary

Every program Tandem Commander starts — the Command Shell command
(`src/cmdshell.cpp`, `SalCreateProcess` with a `NULL` environment block),
`Enter`/double-click on a file (`CFilesWindow::Execute` → `ExecuteAssociation`,
`src/shellsup.cpp:2610`, the shell's default verb invoked in-process), the User
Menu and the command line box — inherits **the environment block of the
Tandem Commander process**. That block is inherited from the parent (normally
Explorer) and then, when *Keep environment variables updated to system
values* is on (the default), rewritten at startup by the undocumented shell32
`RegenerateUserEnvironment` (`src/salamdr7.cpp`, called from
`src/salamdr1.cpp:4470`): the regenerated values replace the inherited ones,
variables the regeneration drops are put back (ANSI API), changed values are
kept regenerated by design. On the reporting machine the result is identical to
Explorer's (spec V6) — nothing is demonstrated broken.

The design therefore has three small work packages, each independently
shippable, all behind the reproduction gate:

1. **Environment guarantee** (FR-001–FR-003): the regeneration logic moves
   into a new pure module `src/common/salenv.{h,cpp}` working on **wide**
   environment blocks behind an injectable OS interface; `salamdr7.cpp` keeps
   a thin wrapper. Semantics change in exactly one place — at startup the
   inherited block is **restored** after the inherited-only set has been
   computed, so the process starts with its parent's environment byte for
   byte; on `WM_SETTINGCHANGE "Environment"` the behaviour stays Explorer's
   (regenerated values win, inherited-only variables re-added, now with exact
   wide values). Details: [research.md](research.md) R2–R4.
2. **Parity check** (FR-004): unit tests of the pure module with fake blocks,
   a process-level self-spawn test in `saltests` (`--dump-env` mode) through
   the same `SalCreateProcess` primitive the Command Shell uses, and the
   manual matrix driven by the `evidence/` scripts
   ([contracts/parity-check.md](contracts/parity-check.md)).
3. **Documentation** (FR-006, FR-009): the *Command Shell* configuration page
   shows that the Windows Terminal preset opens the terminal's *default
   profile*; the manual's two Command Shell topics state what environment the
   program receives, what changes it, and how to compare; CHANGELOG entry at
   the ship gate, truthful about non-reproduction.

## Technical Context

**Language/Version**: C++20 (`/std:c++latest`), MSVC v143 (VS2022), pure WinAPI  
**Primary Dependencies**: none new — `GetEnvironmentStringsW` /
`SetEnvironmentVariableW`, the existing shell32 `RegenerateUserEnvironment`
import (by name, already used), house converters `SalWToU8`/`SalU8ToW`
(WTF-8), `SalCreateProcess`, `TDirectArray`  
**Storage**: none — no registry change; the existing `Reload Environment
Variables` value (`CONFIG_RELOAD_ENV_VARS_REG`, default TRUE) keeps its
meaning  
**Testing**: `saltests` (Debug x64, `build.cmd` → `saltests.exe`, exit code =
failures; 1301 checks at 0.1.7) — new `TestEnvParity073()` + a `--dump-env
<file>` child mode; manual matrix in [quickstart.md](quickstart.md) with
`evidence/capture.cmd`, `penv.ps1`, `treeenv.ps1`, `diag.ps1`;
`tools/check_encoding.py --strict` (runs inside every build); `python -m
translate.slt --verify` for the one new string  
**Target Platform**: Windows 11 and newer, x64; Windows Terminal ≥ 1.24
verified to forward the launcher's environment (spec V3)  
**Project Type**: desktop application — core executable + `src/common`
library shared with `saltests`  
**Performance Goals**: startup unchanged within noise — the regeneration call
(~4 ms, already paid) plus one block copy and at most a few dozen
`SetEnvironmentVariableW` calls (< 1 ms); no per-launch work added  
**Constraints**: plugin ABI untouched (interface 106); no configuration
migration (`MINORB` release); UTF-8/WTF-8 house rules, encoding guard strict
`TOTAL: 0`; the Command Prompt preset's launch stays bit-for-bit (feature 071);
**implementation blocked until FR-005 evidence exists**  
**Scale/Scope**: 1 new common module (+ 2 vcxproj entries), edits confined to
`salamdr7.cpp` (wrapper), `saltests.cpp`, `dialogs4.cpp` (one *Found at*
suffix), 1 new string × 8 languages, 2 edited help topics, CHANGELOG

**Structure Decision**: single-solution desktop application. The only new
module is `src/common/salenv.*`, placed in `src/common/` because `saltests`
compiles `src/common/*.cpp` only (never main-application sources), which is
what makes the diff/apply semantics unit-testable with fake blocks. The OS
calls (`GetEnvironmentStringsW`, `SetEnvironmentVariableW`, the shell32
regeneration) sit behind `CSalEnvOs` so the core supplies the real machine and
the tests a fake — the same probe pattern feature 071 used for the preset
locator.
