# Data Model: Fix File Operations on Names with Unpaired Surrogates

**Feature**: 066-fix-surrogate-filenames · **Date**: 2026-08-22

This feature changes no persistent data structures and no struct layouts. It
redefines the *encoding contract* of one existing field class and the
derivation rules around it.

## Entities

### Directory entry name (operational identity)

| Aspect | Definition |
|--------|------------|
| Authoritative form | The on-disk name: an arbitrary sequence of 16-bit units as returned by `FindFirstFileW`/`FindNextFileW` (`WIN32_FIND_DATAW::cFileName`). May contain unpaired surrogates; is not guaranteed to be valid Unicode text. |
| Internal form | `CFileData::Name` and every path string flowing through the feature-004 facades: **WTF-8** bytes (see [contracts/name-encoding-wtf8.md](contracts/name-encoding-wtf8.md)). For every valid Unicode name this is byte-identical to today's UTF-8. |
| Produced by | `SalWToU8`/`SalWToU8Alloc` (total encoder), fed by `SalConvertFindDataW` at enumeration intake and by every W→U8 facade round trip. |
| Consumed by | `SalU8ToW`/`SalU8ToWAlloc` → wide WinAPI calls (`SalPathToWExtAlloc`, `SalCreateFile`, `SalDeleteFile`, `SalCopyFile`, `SalMoveFileEx`, `SalGetFileAttributes*`, shell operations, process/clipboard hand-off), registry facade values, name comparison/sorting. |
| Validation rules | Round trip W→U8→W MUST be the identity for every unit sequence. U8→W MUST reject all malformed input other than the surrogate 3-byte sequences (preserves the "valid UTF-8, else ANSI" transitional heuristics). |
| Identity/equality | Byte equality of WTF-8 ⇔ unit equality of the on-disk name. Names differing only in unrepresentable units have different WTF-8 bytes and MUST remain distinct in selection, comparison, and operations (spec FR-006). Linguistic comparison (`SalCompareNamesUTF8`) falls back to deterministic byte order when NFC normalization fails on surrogate-bearing names. |

### Display name (derived, one-way)

| Aspect | Definition |
|--------|------------|
| Form | Wide string produced by `SalU8ToWDisplay`/`SalU8ToWDisplayAlloc` for painting and measurement only. |
| Derivation | WTF-8 surrogate sequences decode to their true UTF-16 unit (rendered by the font as the notdef box, matching Explorer); any other malformed byte degrades to `U+FFFD` — one bad unit costs one glyph. |
| Constraint | Never used as a source for path composition, comparison, or any operation (spec FR-005). The derivation is one-way: there is no display→name conversion. |

### Fixture set (test data, not shipped)

| Aspect | Definition |
|--------|------------|
| Location | `temp\fixtures-066\` (generated by quickstart script; `temp\` is not part of any build output or installer). |
| Contents | Files/folders covering: lone high surrogate (the reported repro), lone low surrogate, surrogate as first/last unit, multiple surrogates, look-alike sibling pair (`U+D800` vs `U+D801`), surrogate-named folder with ordinary children. |

## State transitions

None. Names are immutable identities; rename replaces one identity with
another through the same encode/decode pair.

## Invariant summary (binding form in the contract)

1. **Lossless round trip**: `SalU8ToW(SalWToU8(w)) == w` for every wide name.
2. **UTF-8 compatibility**: valid Unicode input ⇒ output byte-identical to
   strict UTF-8 (no change for existing names, config, caches).
3. **Failure preservation**: `SalU8ToW` still fails for malformed non-WTF-8
   input (ANSI-fallback heuristics keep working).
4. **Display is one-way** and substitution never leaks into operations.
5. **Registry facade** stores WTF-8 values as their true UTF-16
   (write-side probe is WTF-8-aware; read side round-trips by construction).
